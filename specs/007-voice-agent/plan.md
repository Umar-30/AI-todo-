# Implementation Plan: Voice-Based AI Agent

**Branch**: `007-voice-agent` | **Date**: 2026-01-23 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/007-voice-agent/spec.md`

## Summary

Add voice input/output capability to the Todo AI Chatbot. The voice agent accepts audio via POST, transcribes using OpenAI Whisper, processes through the existing TaskAgent (MCP tools), and returns synthesized audio via OpenAI TTS. The system remains stateless, with text stored in the database (not audio).

## Technical Context

**Language/Version**: Python 3.11+
**Primary Dependencies**: FastAPI, OpenAI Python SDK, python-multipart
**Storage**: Neon PostgreSQL (existing - no changes)
**Testing**: pytest, httpx
**Target Platform**: Linux server / Docker
**Project Type**: Web application (backend)
**Performance Goals**: <8 seconds end-to-end response time, 50 concurrent requests
**Constraints**: Stateless, MCP-only tool access, <25MB audio input
**Scale/Scope**: Same as text chat - conversation persistence, multi-user

## Design Decisions

### 1. STT Service: OpenAI Whisper via OpenRouter

**Decision**: Use OpenAI Whisper API through existing OpenRouter integration.

**Rationale**:
- Already integrated (same API key, similar SDK usage)
- Industry-leading accuracy (95%+)
- Supports common audio formats
- Stateless API call

### 2. TTS Service: OpenAI TTS

**Decision**: Use OpenAI TTS API for audio synthesis.

**Rationale**:
- Consistent vendor with STT
- Natural-sounding voices
- Simple text-in, audio-out API
- MP3 output for universal playback

### 3. Audio Transmission: Base64 in JSON

**Decision**: Return audio as base64-encoded string in JSON response.

**Rationale**:
- Simplifies client implementation
- JSON response includes all metadata (transcript, tool_calls)
- Works with existing frontend patterns
- Streaming can be added later if needed

### 4. Error Handling: Spoken Errors

**Decision**: Transcription failures return spoken error messages (audio).

**Rationale**:
- Voice-first UX - errors should also be heard
- Includes text fallback for accessibility
- Graceful degradation

## Implementation Approach

### Phase 1: Voice Service Layer

1. Create `VoiceService` class with:
   - `transcribe(audio_bytes, content_type) -> TranscriptionResult`
   - `synthesize(text, voice) -> bytes`

2. Handle API errors gracefully with fallback messages

### Phase 2: Voice Endpoint

1. Create FastAPI router in `api/voice.py`
2. Handle multipart/form-data (audio file + optional conversation_id)
3. Validate audio format and size
4. Integrate with existing conversation management

### Phase 3: Integration with TaskAgent

1. Transcribe audio → text
2. Call existing `TaskAgent.run()` with transcription
3. Synthesize response → audio
4. Return combined response

### Phase 4: Error Handling

1. Transcription failures → spoken clarification request
2. TTS failures → text-only response with error flag
3. Audio format errors → 400 with supported formats
